# Direct MOSS runtime API

`MossSession` is the inference implementation used directly by the benchmark and installed ComfyUI nodes. It does not execute an older benchmark, launch an inference subprocess, rewrite arguments, or patch the global ComfyUI memory manager. The benchmark owns argument parsing, fixed process caps, source snapshots, Tensor hashes, artifact I/O and external telemetry.

```python
config = RuntimeConfig(candidate="q5_ridge_gptq", profile="6g",
                       attention="auto", qkv_backend="shared", host_arena=True)
session = MossSession(config)
positive, negative = session.encode_pair(full_positive, full_negative)
latent = session.sample(positive, negative, empty_flux2_latent, seed,
                        noise=frozen_noise, steps=16, cfg=3,
                        sampler_name="euler", scheduler="sgm_uniform",
                        shift=5, slg_layer=22)
image = session.decode(latent)
session.close()
```

`positive` and `negative` are ordinary ComfyUI CONDITIONING values. `empty_flux2_latent` is a LATENT dictionary with FP32 `samples` shape `[1,128,height//16,width//16]`; the current bridge supports batch one. When noise is omitted, `comfy.sample.prepare_noise` supplies ordinary seed noise. A caller can pass `callback_factory=latent_preview.prepare_callback` for normal preview/progress. Normal ComfyUI interruption propagates, and request scratch plus incomplete DiT state are cleaned in `finally`. The validated control setting is SFT, 16 Euler steps, CFG 3, sgm_uniform, shift 5 and SLG layer 22; other exposed sampler settings are user choices, not an exactness claim.

## R4 current API additions (SM89 / PCIe Gen4 ×4)

The historical round2/SM75 qualifications below are retained as versioned evidence; the R4 changes in this section supersede their current SM89 budget/dtype statements.

- `profile` now also accepts `8g`, `12g`, `16g`; all bounded profiles use allocator caps 3.5/5.5/7.5/11.5/15.5 GiB. Normal node contexts restore the prior cap; benchmark processes enforce their cap throughout.
- `precision="fp16_fixed"|"bf16"` chooses actual floating DiT weights and activation boundaries. BF16 does not apply the FP16 correction; integer codes, FP32 scales, rotation/A8, INT32 accumulators and ordered dequantization are retained. BF16 is rejected on pre-SM80 hardware.
- `vae_precision="fp32"|"bf16"` is independent. BF16 decoding retains original FP32 normalization statistics and latent de-normalization, then uses BF16 convolution. The public VAE input dtype stays FP32, including dynamic ModelPatcher loading. This instance is decode-only; normal encoding requires the normal VAE loader.
- `attention` adds `cudnn`, `sage_fp16`, `sage_fp8`, `sage_fp8_fast`, `sage_fp16_rot`, `sage_fp8_rot`, `ck_int8`. `sage_fp8_rot` is the **fast** FP8 branch plus matched H128. These new adapters require the qualified SM89 environment. The old Flash adapter remains separate for SM75.
- `attention_head_group=-1` automatically selects 8 for Sage/CK in 4g or W8/6g, otherwise 0. Explicit 0/24 disables grouping; 8/12 keeps full K/V while splitting heads. Flash/auto accept only the ungrouped effective setting. The node exposes -1 as `auto`.
- `resident_blocks=-1` chooses a qualified DiT prefix. Explicit 0..40 opts into partial payload streaming. W6/W8 4g automatically stream original immutable codes with two slots, preserving negative-branch SLG layer22 prefetch ordering. Scales remain original FP32. This new owner is SM89-only.
- `payload_pinning="staging"|"suffix"`: streaming staging uses two small pinned buffers. For the complete W8 arena, staging instead uploads the pageable arena as one slab; suffix adds a bounded pinned copy of the suffix. The 2.5 GiB limit counts logical tensor bytes, not rounded physical pinned allocation or process RAM. The installed Torch 2.10 host allocator rounds to powers of two; the previous single-allocation 2052 MiB W8/4g long-case suffix owned a 4 GiB block. When that rounded allocation would exceed the logical pin budget, the current implementation uses power-of-two pieces, so this suffix uses 2048+4 MiB. Consumers copy chunk intersections directly into the existing GPU slot, without concatenation, a second GPU weight buffer or changed integer bytes. Process pinned usage still includes other active allocations and cached blocks. Session close/config replacement releases owned references and then calls the available host-cache release API to return process-wide reusable pinned blocks. Active tensors and unresolved event dependencies remain allocator-owned. Normal per-request DiT disposal does not purge the host pool.
- `host_arena=True` reuses original W5/W6 packed codes. On SM89 W8/6g and W8/8g it also enables a bounded 5 GiB raw-code cache containing 4,756,340,736 bytes (4.4296875 GiB) of original INT8 projection codes. One GPU slab holds all 252 views; there are no per-layer stream hooks in this complete-resident owner. GPU unload restores CPU views without copying immutable codes back from GPU. A later rebuild uploads once, while a surviving GPU owner uploads nothing. First CPU assembly is measured separately and can be expensive; disabling this option retains the prior W8 upload path. Automatic W6/W8 4g streaming owns its raw-code cache independently.
- `te_memory="auto"|"ring"|"partial"|"resident"`; `te_resident_gib` applies only to explicit partial mode. CPU embedding remains CPU. Partial mode owns the constant prefix and uses the original mixed-layer streamer's separate suffix pools; those pools are closed after encoding. Comfy's resident TE lease reports the actual retained prefix bytes and records eviction.
- `vae_admission=True` uses guarded, same-model/runtime/shape calibration with margin. It accounts for already-loaded model bytes and physical free plus reusable allocator cache. Unknown shapes retain the upstream estimate and OOM-to-tiled fallback. It does not increase the profile cap or prove arbitrary merged workloads fit.
- `adapter_cache` remains optional; BF16 tensor identities hash original bytes without conversion. `conditioning_schedule` retains original computed modulation boundaries and applies only to eligible 4g Euler requests; its table preparation is timed separately.

The R4 benchmark explicitly uses original frozen noise, fresh full positive/negative encoding each request, 16 steps, CFG3, Euler/sgm_uniform/shift5, negative SLG22, batch1. Ordinary ComfyUI may cache unchanged text-node outputs for new-seed requests; that experience is measured separately. Stage times exclude artifact saving. Empty compiler cache is not OS disk cache.

The installed runtime does not import scripts or records from the benchmark directory. Review R4 `report/delivery.json` and measured `receipt.json` for final source/combination qualification; current matrix and UI results are not inferred from the historical sections below.

## Ownership and reuse

The session config is immutable. `close()` releases owned TE, DiT, VAE and bounded CPU arena resources; the same cached session object safely lazy reopens on a later call. Production node stages use `resources.allocator_budget`, which activates only one session config per CUDA device, closes an older config, temporarily sets the selected 3.5/5.5/7.5/11.5/15.5 GiB cap for the 4/6/8/12/16 GB profile, and restores the caller's original allocator fraction even after an exception. Benchmark process caps are set before allocation instead.

The 4 GB path retains the CPU ring TE owner, computes the request text adapter before whole-DiT upload, then constructs a fresh disposable DiT for each request. A qualified CPU host arena avoids repeat packing; its cache hits do **not** avoid the full packed-weight H2D transfer. The 6 GB path reuses a complete resident DiT when capacity permits. Heavier W6/W8 models and large decode stages explicitly discard the core before VAE when the bounded plan requires it. A model offloaded by ordinary ComfyUI management is detected by its storage signature and rebuilt, rather than reusing stale installed workspaces.

Packed decoding uses the one canonical `storage.FrozenPackedBase` class and a per-session `SessionScratch`. No decoder or class is globally monkeypatched. Scratch is borrowed only on its bound request stream and host thread, closed after sampling, and recreated before the next request. The packed host cache has a 4 GiB bound; the separate original-code payload cache has a 5 GiB bound. Both release their owned references on close/config replacement.

## Qualification boundaries

- `attention="auto"` retains the original backend. Explicit Flash FP16 is separately qualified on SM89 and SM75 and changes images; it is not lossless.
- INT8 ConvRot and official W4A8 GPTQ TE are independent weight choices. W4A8 is faster in fresh encoding tests but changes conditioning and final images.
- `register3`, FFN lifetime and writer-epilogue flags are explicit candidates until their recorded full-image/capacity gates pass. Microkernel timing does not establish request-level speedup.
- W8 uses its original stored INT8 projection path, with `effective_qkv_backend="stored_int8_separate"`. It does not acquire W5/W6 bit packing or fused packed QKV. R4 SM89 supports its separate original-code streaming/complete-resident arena described above; the prior SM75 projection dispatch remains unchanged.
- Resident TE uses CPU embedding with the full GPU decoder. The standard ComfyUI text lease has passed real eviction/reopen tests; tiny CPU lease tests alone were not used as sufficient evidence. An automatic eviction is recorded and never counted as persistent reuse.
- `strict_full_vae=True` is an explicit diagnostic option that disables tiled fallback. R4 normal request benchmarks and production preserve official fallback and record the effective decode mode.
- This frozen SFT API does not accept LoRA patches. The original native Base/LoRA workflow remains separate.

Source and upstream license manifests are kept in `vendor`. Production packaging must copy this runtime into the node package and preserve those manifests/licenses; an installed node must not depend on the benchmark directory.


## Qualified automatic policy (SM89, round2)

The ordinary nodes use `qkv_backend="auto"` and `ffn_tile=-1` (the UI calls this `auto`). `profile_plan.kernel_plan` runs once at the request boundary. It counts `joint_N = latent_H * latent_W + max(positive_tokens, negative_tokens)`, using full, untruncated conditioning lengths. The receipt records both requested and effective settings.

For W5 at the 4g allocator budget, joint N up to 5894 uses shared activation quantization and full-token FFN. Joint N from 5895 through the qualified maximum 10206 selects register QKV with private normalized-input Q reuse, the original in-place Q/K normalization and RoPE kernel, single-frame original-plan execution, FFN 2048-row tiles, and attention-output projection 2048-row tiles. This combination completed test_00207 with conditioning and final latent bitwise equal to the 6g reference. The full FP32 VAE really exceeded the 4g budget; the official tiled fallback completed and changed RGB (maximum 32/255, MAE 3.3576/255 for that case). This is not final-pixel exact. Shapes beyond the qualified automatic 4g joint-N range fail clearly instead of silently selecting an untested kernel combination. W6/W8 production choices are qualified at 6g, not 4g.

The single-frame implementation preserves the original ExecutionPlan steps, runner calls, skipped-layer rescaling, mask handling, stream casts, and head. It removes the outer caller reference to the initial embedded joint tensor. Before the fix, test_00207 failed in the first NFE at block 1 SDPA, while a weak reference proved the initial 62,705,664-byte embedding remained alive alongside a different current residual. With the fix that weak reference was dead at blocks 1 and 41; subsequent same-branch NFE start allocation was stable. It does not remove the original JointBlock input lifetime through its FFN.

SM89 unlimited uses a truly resident text decoder with CPU embedding lookup. The CPU lookup is only the embedding stage, not the full encoder. To retain TE safely through decoding, each request discards DiT before VAE, retains the bounded CPU packed arena, and rebuilds/uploads DiT on the next request. A host-arena hit avoids repacking; it does not remove the next GPU weight upload. For the measured exact FP32 VAE shapes only, the VAE stage temporarily limits the whole-process PyTorch allocator to current allocated bytes plus at most 5.5 GiB, constrained by physical free memory and a 1 GiB margin. The instance activation estimate is bounded for this stage, and both estimate and prior allocator fraction are restored in finally. This is explicitly an adaptive VAE-stage budget, not an unrestricted allocator throughout the request. Other shapes or architectures retain the upstream memory-manager estimate and safe eviction behavior. Six SM89 cases completed with fresh encoding, zero subsequent TE weight H2D, conditioning/latent bitwise equal, and full-VAE RGB differences of at most one colour level. Standard Comfy unload removed the resident TE and a later encode reopened it with identical conditioning.

## USB4 SM75 policy and memory ownership

The measured USB4 RTX 2080 Ti has 22 GiB physical VRAM. It runs the same Torch 2.10 CUDA13 runtime with one isolated Triton 3.2 installation selected before process startup, and a real VS build-tools shell. The main SM89 process retains Triton 3.6; neither process swaps Triton modules at runtime.

SM75 ring INT8C and official W4A8 q17 encoding were compared with the upstream encoder on that same GPU. Both candidate paths preserved their own upstream conditioning exactly; W4A8 versus INT8C remains an independent, image-changing weight comparison. Delta-rule and causal attention use upstream eager fallbacks because the Triton variants require SM80+. CPU embedding lookup is only the embedding stage. The full decoder still executes on GPU.

For SM75 6g and unlimited, automatic policy keeps original native FFN and shared QKV activation quantization. Fused register alternatives were slower on this architecture in actual microbenchmarks, so they are reserved for capacity needs. All six 6g cases completed with full FP32 VAE. On this measured 22 GiB device, unlimited keeps both the text decoder and packed DiT across requests: one DiT upload/build and five reuses in six fresh prompts, with zero TE weight H2D after initial resident loading. All six conditioning, final latent and RGB results matched this GPU's 6g controls bitwise. These are measured cases, not a cross-GPU bitwise promise. The same reversible, exact-shape-qualified VAE stage budget is applied with both resident owners included in its base; prior allocator fraction and instance estimate are restored.

The core uses a buffer-aware standard ComfyUI ModelPatcher. `loaded_size` deduplicates actual CUDA storages, including packed buffer-only leaves. A partial-unload request conservatively moves the entire packed core to CPU rather than claiming paging support. The measured bounded partial call freed exactly 3,169,449,024 bytes of registered core storage. Subsequent standard unload removed TE and core CUDA storage, closed scratch/workspaces and reduced actual allocator use to about 18 MB. The next request detects CPU placement, invalidates stale bindings and rebuilds. This does not mutate ComfyUI's loaded-model list during callbacks or register a second, double-counted core lease. CPU host arenas remain bounded and can survive ordinary GPU unloading; explicit session close releases them.

SM75 4g uses shared QKV plus FFNv3 for small sequences. q03, q02, q17, test_00200 and balcony completed with conditioning, latent and RGB bitwise equal to the same-card 6g controls. The measured large-sequence fallback combines private-input Q reuse, original in-place RoPE, private embed writes, the single-frame original plan, FFN/output projection tiles and optional query-M SDPA tiles plus CPU exact text guards. The complete test_00207 fallback passed all 32 model evaluations with conditioning/latent bitwise equal; official tiled VAE changed RGB (maximum 34/255, MAE 3.3066/255 in the measured diagnostic run). The final no-diagnostic v6 completed in DiT 117.7702 s and VAE 16.7398 s with allocator peak 3,582,754,304 bytes. The one v7 ablation removed query tiling and restored GPU text guards after fixing the exception cache; it still failed on the second Euler step allocating full SDPA output. Consequently `sdpa_capacity_fallback=True` remains the production default, effective only for the SM75 4g large-sequence auto path. Other profiles retain full SDPA and original GPU guards. This is a measured capacity choice, not a speed claim.

A cold long-prompt failure exposed an upstream diagnostic-cache lifetime bug. The kernel-choice probe and two tuner failure caches kept an exception object that was later raised; its traceback retained the entire failed TE call's GPU inputs and FP32 Hadamard temporaries. The snapshot's retained requested sizes matched `2119 * 4096 * 4` and `2119 * 4096 * 2`. The bundled fork now stores an independent never-raised diagnostic copy and raises a different fresh copy, preserving the known exception class, exact message, op, error texts, persistence and problem identifier without context/cause/traceback. No arithmetic or selected fallback changed. Actual cold test_00207 then finished with TE-complete allocated memory of 8,659,968 bytes. Its explicit GC measured the same allocation before and after, so that capacity recovery is attributed to removing persistent exception roots, not to GC. The stage GC runs only for the SM75 4g profile; it does not add overhead to unlimited warm text encoding. Original failed runs and CPU weak-reference reproductions remain separate evidence.

## Exact input and fallback boundaries

The current sampler bridge accepts batch one and a LATENT `samples` tensor `[1,128,H,W]`; ordinary EmptyFlux2LatentImage uses the MOSS 16x spatial compression. Image dimensions and prompts are not silently resized or truncated by this session. The measured pixel sizes are 1024x1024, 1376x768, 1248x1664 and 1280x800. Other shapes are not all covered by these measurements.

The explicit automatic joint-token ceiling `10206` applies to the W5/W6 **4g auto-QKV planner on SM89/SM75**. `joint_N = latent_H*latent_W + max(positive_tokens,negative_tokens)`. Larger auto 4g requests fail with a clear error directing the caller to a larger budget or smaller image. It is not a global 6g/unlimited ceiling. R4's new W6 qualification is on SM89; listing the planner guard does not claim a new SM75 test. Expert QKV overrides bypass that auto planner and do not acquire a capacity guarantee.

The 6g/unlimited paths do not impose this token ceiling. They can still exceed actual memory and propagate a clean OOM after releasing incomplete request state. The adaptive resident-VAE stage estimate is qualified only for latent shapes `(64,64)`, `(48,86)`, `(104,78)` and `(50,80)` with this exact FP32 MOSS VAE. Unknown shapes keep the upstream estimate and conservative stage disposal/standard model-manager eviction rather than extrapolating measured activation peaks. This can evict TE and reduce later reuse; it is recorded, not hidden. Normal VAE decode retains the official OOM-to-tiled fallback, and the receipt distinguishes it from full decode. Strict no-tile mode is a benchmark qualification option, not the production default.

Explicit Flash supports the validated FP16 H24/D128 single-full-segment bridge on SM89/SM75; R4 additionally qualifies the actual BF16 bridge on SM89. Unsupported architecture/dtype/layout fails rather than silently substituting a different attention backend. The frozen session does not support LoRA or arbitrary runners, multi-image batches or arbitrary external model mutations. Complete prompts are preserved; successful tests cover positive lengths up to 2094 tokens, not every possible context length.
